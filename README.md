# BTaskAssistant

BTaskAssistant 是一款面向 AI 辅助开发的桌面任务工作流客户端。它把聊天、文档、图片、任务面板信息和项目证据整理为可追溯的任务，使用 PI/OMP、Codex 等执行器参与需求访谈与开发，并把关键决策始终留给用户。

## 不可变原则

- AI 只能提取候选任务、发现疑问、生成草稿、执行获批范围和提出审查意见。
- AI 不能批准需求、批准开发提示词或把任务标记为完成。
- 未绑定项目不进入需求分析；未批准需求不进入开发；未人工验收不进入完成。
- 需求事实必须能追溯到原始资料、用户回答或固定项目快照。
- 执行器报告“开发完成”只会把任务推进到 `WAITING_REVIEW`。
- 开发默认在 GitHub 关联的 Work/Codex 远端临时环境中进行。
- 用户本地长期保存需求资料、文档、图片、运行产物和必要配置，不长期保存项目源码。

## 核心流程

```text
资料收集
→ 固定程序解析 / AI 候选提取
→ 人工创建或关联任务
→ 绑定项目与选择分析资料
→ AI 需求访谈
→ 人工批准需求与开发提示词
→ PI/OMP 或 Codex 开发
→ 人工测试或独立 AI 审查
→ 人工批准的定向修复
→ 人工最终验收
```

## 开发方式

GitHub 仓库是项目源码与正式文档的唯一长期真相源。推荐流程：

1. 在 GitHub 关联的 Work/Codex 环境按目标提交或分支创建临时检出。
2. 先在 `docs/codex-tasks/<task-slug>/` 完成需求规划并等待人工批准。
3. 用户明确触发范围受控开发；完成后审查 diff 和实施报告。
4. 用户明确触发定向自测；必要时最多进行两轮有证据的最小修复。
5. 通过提交或 PR 将获批结果保存在 GitHub；远端/临时检出按策略清理。

用户电脑不需要长期维护 BTaskAssistant 或目标项目的源码副本。客户端本地只保存控制面数据；如用户明确选择本地执行，源码只能位于现有用户项目或本次运行的临时目录，不能进入 BTaskAssistant 数据目录，运行结束后必须显示并执行清理结果。
