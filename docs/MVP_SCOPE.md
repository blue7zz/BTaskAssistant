# 第一版范围

这一版是完整目标架构的首个可运行纵向切片，不代表已经完成全部基础设施。

## 状态映射

当前界面先把目标架构中的细状态合并成六个用户可理解的阶段：

| 当前阶段 | 对应目标状态 |
| --- | --- |
| 任务池 | `INBOX`、`TASK_READY` |
| 需求整理 | `ANALYZING`、`WAITING_CONFIRMATION` |
| 待开发 | `REQUIREMENT_APPROVED`、`READY_FOR_DEVELOPMENT` |
| 开发中 | `DEVELOPING` |
| 待审核 | `WAITING_REVIEW`、`CHANGES_REQUESTED` |
| 已完成 | `COMPLETED` |

`BLOCKED`、`ARCHIVED`、独立 RequirementRevision / PromptRevision 和追加式 ExecutionRun 会在领域表拆分时加入；第一版没有用虚假的自动状态代替这些能力。

## 已实现

### 任务收集

- 手动录入标题、说明、项目和优先级。
- 粘贴聊天记录导入。
- 搜索和按阶段筛选任务。
- 添加、查看和删除需求来源。

### 需求整理

- 目标、范围内、范围外、验收标准、风险与约束编辑。
- 根据已有字段和来源生成固定结构的需求文档。
- 为事实附上来源编号。
- 对缺失信息生成待确认问题。
- 生成带“严禁假设”和停止条件的执行提示词。
- 需求人工确认、锁定、撤销确认。

### 开发与审核

- 选择 Codex 或 PI / oh-my-pi 作为外部执行工具。
- 复制确认后的执行提示词。
- 手动记录委托状态、开发结果和验证信息。
- 生成基础审核清单。
- 逐项核对、记录审核证据、人工批准。

### 基础设施

- Wails v2 + Go 桌面工程。
- React / TypeScript / Vite / Zustand 前端。
- Wails 本机 SQLite 持久化与浏览器回退。
- Go 与 TypeScript 双层状态转换门禁。
- 单元测试和 GitHub Actions。

## 明确未实现

以下内容没有足够的已确认信息，因此第一版不会自行假设：

- 直接启动 PI、oh-my-pi 或 Codex 进程；
- 自动读取 GitHub、聊天软件、任务面板或本地项目；
- AI 自动修改需求、回答待确认问题或批准审核；
- 多机器同步、账号体系或团队协作；
- 多工作树并行开发调度；
- 自动提交、合并、回滚或删除 Git 分支；
- 复杂项目配置和密钥管理。

## 下一版接入前必须确认

1. PI / Codex 的具体 CLI 命令、版本和结构化输出。
2. 项目目录如何登记和授权。
3. 执行进程的超时、中断、恢复和并发上限。
4. 开发结果与审核结果的可信证据格式。
5. 是否接入 GitHub、聊天记录或任务面板，以及每个来源的读取权限。
