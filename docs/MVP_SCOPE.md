# 第一版范围

这一版是完整目标架构的首个可运行纵向切片，不代表已经完成全部基础设施。

## 状态映射

当前界面先把目标架构中的细状态合并成六个用户可理解的阶段：

| 当前阶段 | 对应目标状态 |
| --- | --- |
| 任务池 | `INBOX`、`TASK_READY` |
| 需求整理 | `PREPARING`、`ANALYZING`、`WAITING_USER_ANSWER`、`AI_SUGGESTED_READY`、`FORCE_PROCEED_CONFIRMATION`、`DRAFT_READY`、`BLOCKED` |
| 待开发 | `REQUIREMENT_APPROVED`、`READY_FOR_DEVELOPMENT` |
| 开发中 | `DEVELOPING` |
| 待审核 | `WAITING_REVIEW`、`CHANGES_REQUESTED` |
| 已完成 | `COMPLETED` |

主任务级 `BLOCKED`、`ARCHIVED`、独立 RequirementRevision / PromptRevision 和追加式 ExecutionRun 会在领域表拆分时加入。需求整理内部已经记录分析受阻状态，但不会借此自动改变主任务阶段。

## 已实现

### 任务收集

- 手动录入标题、说明、项目和优先级。
- 粘贴聊天记录导入。
- 搜索和按阶段筛选任务。
- 添加、查看和删除需求来源。

### 需求整理

- 三栏需求工作区：上下文资料、AI 访谈、实时需求草稿。
- 选择参与分析的资料，并登记供 AI 只读检查的本地项目目录。
- 选择 PI 或 Codex 执行多轮结构化需求分析，也可调用另一个 AI 独立复查。
- 问题按阻塞、重要和可选分级，支持回答、跳过和标记不在范围内。
- AI 草稿更新保持为候选，用户明确采纳后才写入实时草稿。
- 用户可以带着显式策略强制推进；未确认事项和风险不会被隐藏或自动回答。
- 根据已有字段、来源、用户回答和项目观察生成 12 节需求文档。
- 为事实附上来源编号，并把代码观察单独标记为 `PROJECT_OBSERVATION`。
- 生成带“严禁假设”和停止条件的执行提示词。
- 需求人工确认、锁定、撤销确认。
- 每次批准保留不可变需求文档与执行提示词快照，后续草稿不会静默覆盖历史版本。

### 开发与审核

- 选择 Codex 或 PI / oh-my-pi 作为外部执行工具。
- 复制确认后的执行提示词。
- 手动记录委托状态、开发结果和验证信息。
- 生成基础审核清单。
- 逐项核对、记录审核证据、人工批准。

### 基础设施

- Wails v2 + Go 桌面工程。
- React / TypeScript / Vite / Zustand 前端。
- Wails 本机 SQLite 持久化与浏览器回退。
- Go 与 TypeScript 双层状态转换门禁。
- 单元测试和 GitHub Actions。

## 明确未实现

以下内容没有足够的已确认信息，因此第一版不会自行假设：

- 用 PI、oh-my-pi 或 Codex 自动执行开发任务；
- 未经用户绑定和只读授权扫描本地项目，或自动读取 GitHub、聊天软件和其他任务面板；
- AI 自动修改需求、回答待确认问题或批准审核；
- 多机器同步、账号体系或团队协作；
- 多工作树并行开发调度；
- 自动提交、合并、回滚或删除 Git 分支；
- 复杂项目配置和密钥管理。

## 下一版接入前必须确认

1. 需求分析长任务的中断、恢复和并发上限。
2. 独立 RequirementRevision 表及已批准版本的追加式历史。
3. 开发执行进程的工具审批、工作树隔离和失败恢复。
4. 开发结果与审核结果的可信证据格式。
5. 是否接入 GitHub、聊天记录或其他任务面板，以及每个来源的读取权限。
