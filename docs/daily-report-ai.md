# AI 日报生成说明

## 资料归并

本功能将用户提供的日报提示词、公司文档索引、Git 采集脚本、原 HTML 填报工具、Cursor Skill 与历史日报样例归并为一条应用内流程。规则冲突时以日报提示词和输出格式标准为准；历史样例只用于校验表达与结构，不作为事实来源。原资料中存在不同默认姓名和工号，因此实现不写死个人身份，统一从“设置 → 日报设置”读取。

Git 采集脚本的行为由 Go 后端等价实现：只读取所选仓库的分支、指定日期提交摘要和文件统计；开启选项时额外读取未提交状态与统计。不会读取 diff 正文、远端地址或 Git 邮箱，也不会把仓库绝对路径交给 AI。

## 固定规则

- 锚点字段与顺序固定为 `REPORT-ORG`、`LEVEL`、`TYPE`、`DATE`。
- 正文固定为“今日结果、死锁阻碍、专项复盘、明日动作”四段，空段导出 `- 无`。
- 今日结果必须包含任务、状态、进度和已有证据；多条提交按业务意图合并。
- 未提交内容只能表述为进行中；无法从输入证明的信息不得补全。
- 明日动作最多 TOP1–3；由进行中内容推断的动作必须标记“待确认”。
- AI 只填写结构化事实字段，不直接编写整行日报文本。今日结果分别返回任务、状态、进度和证据；阻碍、复盘、明日动作也按固定字段返回。
- 应用代码统一补齐项目占位、分隔符、TOP 顺序和“待确认”，折叠换行并转义模板保留符；同时过滤 `manualDescription`、`workflowTasks`、`gitContext` 等内部输入字段名，避免它们被当成业务证据写入表单。
- 预览和“确认填入表单”使用同一份代码格式化结果。预览不会修改表单；当前日期已有正文时会显示覆盖提示，用户点击一次确认后直接替换四段正文。

这些规则属于公司格式和事实边界，不开放为可覆盖配置。附加写作指令只能调整措辞。

## 可配置内容

“设置 → 日报设置”集中管理：

- 填报身份：组织、提交人、工号、层级、岗位。
- AI：PI/Codex、模型、思考强度、执行时限、附加写作指令。
- Git：作者过滤、是否包含未提交状态。
- 项目历史：查看和删除在生成弹窗中使用过的本地仓库。
- 云端提交：API 地址与 Token。

Token 只保存在系统凭据库，不进入 Zustand 持久化数据、Git 上下文或 AI 输入。API 地址、工号和提交人姓名同样不会发送给 AI。

勾选工作流任务时，AI 输入中只包含标题、项目名、当前状态、任务摘要、开发结果与审核备注；不会包含任务 ID、项目路径、原始证据或完整需求/执行提示词。

## 使用流程

1. 在日报页底部点击“AI 生成日报”。
2. 从历史中选择项目或添加本地 Git 仓库，并按需勾选报告日有更新的工作流任务。
3. 在单个“人工补充”输入框中自由描述代码和任务列表之外的事实，无需预先分类。
4. 点击“生成预览”，核对固定四段式 Markdown。
5. 点击“确认填入表单”，再人工修订、复制、下载或上传。

浏览器预览模式不会执行本机 AI；生成需要在 Wails 桌面客户端中使用已安装并登录的 PI 或 Codex CLI。
